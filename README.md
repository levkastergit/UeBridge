# UE Bridge

Связывает два компьютера: **ПК Unreal** (где стоит Unreal Engine) и **ПК Claude** (где работает Claude Code), чтобы Claude Code видел файлы проекта и управлял редактором через MCP (плагин [unreal-engine-skills-for-claude-code](https://github.com/EpicGames/unreal-engine-skills-for-claude-code-plugin)).

Claude Code при этом установлен и работает только на ПК Claude.

Два варианта связи:

- **ПК Claude и ПК Unreal в одной локальной сети** — ПК Claude подключается к ПК Unreal напрямую (сетевая папка + SSH-туннель с ПК Claude).
- **ПК Claude в другой сети** (например, сервер в интернете, а ПК Unreal дома за роутером) — обратный SSH-туннель: ПК Unreal сам подключается к ПК Claude и открывает на ПК Claude (только на `127.0.0.1`) порт MCP-сервера и порт для папки проекта. Роутер ПК Unreal настраивать не нужно. См. раздел «ПК Claude в другой сети».

Программа одна: на ПК с Unreal Engine она открывается в режиме ПК Unreal, на ПК без него — в режиме ПК Claude (переключается кнопкой «Это ПК Claude…» / «Это ПК Unreal…»).

## ПК Claude в другой сети (обратный SSH-туннель)

**ПК Claude** — запустите `UeBridge.exe` (откроется режим ПК Claude) и нажмите «Настроить ПК Claude». Программа:

1. ставит OpenSSH Server и настраивает его: вход **только по ключу** (пароли отключены), разрешена только обратная переадресация портов, разрыв зависших соединений через ~45 с; открывает порт в брандмауэре;
2. создаёт ключ для ПК Unreal. Этим ключом можно только открыть туннель и передать ПК Claude данные о проекте — командную строку на ПК Claude он не даёт;
3. проверяет всё сама — подключается к себе этим ключом и открывает тестовую переадресацию;
4. показывает **код подключения** и кладёт на рабочий стол «Подключить-UE.cmd».

Хостинг ПК Claude должен пропускать входящие соединения на SSH-порт (по умолчанию 22).

**ПК Unreal** — вставьте код в поле «Код подключения от ПК Claude» и нажмите «Подключить к ПК Claude». Программа сохраняет ключ (доступ только у администраторов), создаёт задачу планировщика «UeBridge Tunnel» (от имени SYSTEM, запускается при включении ПК, при обрыве переподключается) и проверяет туннель **со стороны ПК Claude**: отвечает ли MCP-сервер и доступен ли порт папки. «Настроить всё» дальше повторяет эту проверку.

**ПК Claude, каждый раз** — «Подключить-UE.cmd» на рабочем столе (или «Подключить проект» в UeBridge): ждёт туннель, подключает папку проекта как диск (`Z:`) через SMB на порту туннеля и открывает её в Cursor / VS Code (или запускает `claude`). Пароль Windows от ПК Unreal спрашивается один раз и хранится зашифрованным для вашей учётной записи (Windows DPAPI).

Для подключения папки по нестандартному порту нужен Windows 11 24H2 или новее на ПК Claude ([Microsoft: альтернативные порты SMB](https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-ports)).

## Что делает кнопка «Настроить всё»

1. Включает стандартный компонент Windows **OpenSSH Server** (служба sshd, автозапуск, правило брандмауэра на порт 22 для частной сети). Если компонента нет, ставит его через Windows Update. В режиме обратного туннеля этот шаг пропускается — ПК Unreal свой SSH-сервер не нужен.
2. Расшаривает папку проекта по сети (доступ только текущему пользователю Windows).
3. В `.uproject` включает плагины `ModelContextProtocol` (в редакторе называется Unreal MCP) и `AllToolsets` (All Toolsets). Оригинал сохраняется в `.uproject.bak`.
4. Проверяет, не занят ли порт MCP (по умолчанию 8000) другой программой; если занят — выбирает ближайший свободный.
5. Пишет в `Saved/Config/WindowsEditor/EditorPerProjectUserSettings.ini` порт и путь MCP-сервера и автозапуск сервера.
6. Создаёт или дополняет `.mcp.json` в папке проекта записью `unreal-mcp`.
7. Проверяет, что в установленном движке есть плагин ModelContextProtocol.
8. Запускает MCP-сервер:
   - если Unreal Editor с проектом не открыт — открывает его с флагами `-ModelContextProtocolStartServer -ModelContextProtocolPort=<порт>`;
   - если открыт, но запущен до изменения настроек и сервер в нём не работает — спрашивает разрешения и перезапускает редактор. Закрывает его так же, как кнопка × (несохранённые изменения редактор предложит сохранить), и открывает проект заново;
   - ждёт, пока сервер ответит на MCP-запрос `initialize`.
9. Если ПК Unreal связан с ПК Claude кодом подключения — перезапускает туннель и проверяет его со стороны ПК Claude.

Все шаги идемпотентны: кнопку можно нажимать повторно, лишнего она не сделает.

## Кнопка «Проверить состояние»

Ничего не меняет. Проверяет sshd, брандмауэр, сетевую папку, плагины, ini, `.mcp.json` и сам MCP-сервер — запросом по протоколу MCP, а не только открытым портом. Если сервер не отвечает, пишет в журнал причину:

- какая программа занимает порт;
- открыт ли редактор с этим проектом (или с другим) и когда он запущен относительно изменения настроек;
- какие порты слушает редактор;
- строки о MCP из журнала редактора `Saved/Logs/<Проект>.log`.

И подсказывает, исправит ли это «Настроить всё».

## Кнопка «Обновить»

Проверяет на GitHub ([Releases](../../releases)) новую версию программы. Если она есть, открывает страницу релиза, откуда нужно скачать `UeBridge.exe` и заменить файл. Затем заново применяет все настройки (то же, что «Настроить всё»).

## Пошаговая инструкция

Ничего включать в редакторе вручную не нужно — плагины и настройки MCP программа делает сама.

**ПК Unreal (где Unreal Engine):**

1. Скачайте `UeBridge.exe` со страницы [Releases](../../releases) и запустите. Windows спросит разрешение на запуск от администратора — нажмите «Да».
2. «Обзор…» → выберите файл `.uproject` вашего проекта.
3. Нажмите «Настроить всё». Если Unreal Editor с проектом открыт и его нужно перезапустить, программа спросит разрешения. Если редактор при закрытии спросит о сохранении — ответьте в его окне.
4. Дождитесь в журнале строк `OK: MCP отвечает: …` и `=== Готово, ошибок нет ===`. Первая загрузка проекта после включения плагинов может занять несколько минут — программа пишет «…ещё выполняется».
5. Нажмите «Сохранить скрипт для ПК Claude…» и перенесите `.cmd` на ПК Claude.

**ПК Claude (где Claude Code):**

1. Запустите `.cmd` из шага 5. Он подключит папку проекта как диск, откроет SSH-туннель и запустит Claude Code. Пароль — пароль входа в Windows на ПК Unreal. При первом SSH-подключении ответьте `yes` на вопрос о ключе ПК Unreal.
2. В Claude Code один раз установите плагин и проверьте подключение:

```
/plugin install unreal-engine-skills-for-claude-code@claude-plugins-official
/mcp
```

`/mcp` должен показать `unreal-mcp` как подключённый.

**Как посмотреть то же самое в редакторе (необязательно):** Edit → Plugins — включены Unreal MCP и All Toolsets; Edit → Editor Preferences → General → Model Context Protocol — Auto Start Server, порт и путь.

## Для ПК Claude в той же локальной сети

После настройки окно «Данные и команды для ПК Claude» показывает имя ПК Unreal, IP-адреса, имя пользователя для SSH и команды. Кнопка «Сохранить скрипт для ПК Claude…» создаёт `.cmd`, который на ПК Claude:

1. подключает сетевую папку проекта как диск (по умолчанию `Z:`);
2. поднимает SSH-туннель `ssh -N -L 8000:127.0.0.1:8000 user@ПК Unreal`;
3. запускает `claude` в папке проекта.

Пароль для `net use` и `ssh` — пароль входа в Windows на ПК Unreal.

Внутри Claude Code на ПК Claude:

```
/plugin install unreal-engine-skills-for-claude-code@claude-plugins-official
/mcp
```

## Требования

- ПК Unreal: Windows 10/11, права администратора (программа сама запросит), Unreal Engine с плагином ModelContextProtocol.
- ПК Claude: Windows с клиентом `ssh` (входит в Windows 10/11), Claude Code, Git Bash для хука плагина.
- Либо оба ПК в одной локальной сети, либо ПК Claude доступен из интернета по SSH-порту (режим обратного туннеля; на ПК Claude — Windows 11 24H2 или новее).

## Сборка

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0):

```
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -o publish
```

Релиз на GitHub: пуш тега `vX.Y.Z` (версия должна совпадать с `<Version>` в `UeBridge.csproj`) собирает exe через GitHub Actions и прикладывает его к релизу.
