# UE Bridge

Программа для **ПК2** (где стоит Unreal Engine). Одной кнопкой готовит ПК2 так, чтобы Claude Code, установленный на **ПК1**, видел файлы проекта и управлял редактором через MCP (плагин [unreal-engine-skills-for-claude-code](https://github.com/EpicGames/unreal-engine-skills-for-claude-code-plugin)).

Claude Code при этом установлен и работает только на ПК1.

## Что делает кнопка «Настроить всё»

1. Включает стандартный компонент Windows **OpenSSH Server** (служба sshd, автозапуск, правило брандмауэра на порт 22 для частной сети). Если компонента нет, ставит его через Windows Update.
2. Расшаривает папку проекта по сети (доступ только текущему пользователю Windows).
3. В `.uproject` включает плагины `ModelContextProtocol` (в редакторе называется Unreal MCP) и `AllToolsets` (All Toolsets). Оригинал сохраняется в `.uproject.bak`.
4. Проверяет, не занят ли порт MCP (по умолчанию 8000) другой программой; если занят — выбирает ближайший свободный.
5. Пишет в `Saved/Config/WindowsEditor/EditorPerProjectUserSettings.ini` порт и путь MCP-сервера и автозапуск сервера.
6. Создаёт или дополняет `.mcp.json` в папке проекта записью `unreal-mcp`.
7. Проверяет, что в установленном движке есть плагин ModelContextProtocol.
8. Запускает MCP-сервер:
   - если Unreal Editor с проектом не открыт — открывает его с флагами `-ModelContextProtocolStartServer -ModelContextProtocolPort=<порт>`;
   - если открыт, но запущен до изменения настроек и сервер в нём не работает — спрашивает разрешения и перезапускает редактор. Закрывает его так же, как кнопка × (несохранённые изменения редактор предложит сохранить), и открывает проект заново;
   - ждёт, пока сервер ответит на MCP-запрос `initialize`.

Все шаги идемпотентны: кнопку можно нажимать повторно, лишнего она не сделает.

## Кнопка «Проверить состояние»

Ничего не меняет. Проверяет sshd, брандмауэр, сетевую папку, плагины, ini, `.mcp.json` и сам MCP-сервер — запросом по протоколу MCP, а не только открытым портом. Если сервер не отвечает, пишет в журнал причину:

- какая программа занимает порт;
- открыт ли редактор с этим проектом (или с другим) и когда он запущен относительно изменения настроек;
- какие порты слушает редактор;
- строки о MCP из журнала редактора `Saved/Logs/<Проект>.log`.

И подсказывает, исправит ли это «Настроить всё».

## Кнопка «Обновить»

Проверяет на GitHub ([Releases](../../releases)) новую версию программы. Если она есть, открывает страницу релиза, откуда нужно скачать `UeBridge.exe` и заменить файл. Затем заново применяет все настройки (то же, что «Настроить всё»).

## Пошаговая инструкция

Ничего включать в редакторе вручную не нужно — плагины и настройки MCP программа делает сама.

**ПК2 (где Unreal Engine):**

1. Скачайте `UeBridge.exe` со страницы [Releases](../../releases) и запустите. Windows спросит разрешение на запуск от администратора — нажмите «Да».
2. «Обзор…» → выберите файл `.uproject` вашего проекта.
3. Нажмите «Настроить всё». Если Unreal Editor с проектом открыт и его нужно перезапустить, программа спросит разрешения. Если редактор при закрытии спросит о сохранении — ответьте в его окне.
4. Дождитесь в журнале строк `OK: MCP отвечает: …` и `=== Готово, ошибок нет ===`. Первая загрузка проекта после включения плагинов может занять несколько минут — программа пишет «…ещё выполняется».
5. Нажмите «Сохранить скрипт для ПК1…» и перенесите `.cmd` на ПК1.

**ПК1 (где Claude Code):**

1. Запустите `.cmd` из шага 5. Он подключит папку проекта как диск, откроет SSH-туннель и запустит Claude Code. Пароль — пароль входа в Windows на ПК2. При первом SSH-подключении ответьте `yes` на вопрос о ключе ПК2.
2. В Claude Code один раз установите плагин и проверьте подключение:

```
/plugin install unreal-engine-skills-for-claude-code@claude-plugins-official
/mcp
```

`/mcp` должен показать `unreal-mcp` как подключённый.

**Как посмотреть то же самое в редакторе (необязательно):** Edit → Plugins — включены Unreal MCP и All Toolsets; Edit → Editor Preferences → General → Model Context Protocol — Auto Start Server, порт и путь.

## Для ПК1

После настройки окно «Данные и команды для ПК1» показывает имя ПК2, IP-адреса, имя пользователя для SSH и команды. Кнопка «Сохранить скрипт для ПК1…» создаёт `.cmd`, который на ПК1:

1. подключает сетевую папку проекта как диск (по умолчанию `Z:`);
2. поднимает SSH-туннель `ssh -N -L 8000:127.0.0.1:8000 user@ПК2`;
3. запускает `claude` в папке проекта.

Пароль для `net use` и `ssh` — пароль входа в Windows на ПК2.

Внутри Claude Code на ПК1:

```
/plugin install unreal-engine-skills-for-claude-code@claude-plugins-official
/mcp
```

## Требования

- ПК2: Windows 10/11, права администратора (программа сама запросит), Unreal Engine с плагином ModelContextProtocol.
- ПК1: Windows с клиентом `ssh` (входит в Windows 10/11), Claude Code, Git Bash для хука плагина.
- Оба ПК в одной локальной сети.

## Сборка

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0):

```
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -o publish
```

Релиз на GitHub: пуш тега `vX.Y.Z` (версия должна совпадать с `<Version>` в `UeBridge.csproj`) собирает exe через GitHub Actions и прикладывает его к релизу.
